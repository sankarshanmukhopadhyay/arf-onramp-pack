# Upstream Sync Resolution — August 2026

This record provides the human-review evidence for monitor-generated issues #5, #6, and #7. The review separates substantive upstream changes that require local companion updates from monitoring-state transitions that do not represent authority drift.

## Disposition register

| Issue | Source | Finding | Disposition | Local action | Closure evidence |
|---|---|---|---|---|---|
| #5 | `arf` | Default branch moved from `299b7da` to `6373eee`; the watched annex set changed while the authoritative release remained `v3.0.0`. | **Accepted ARF 3.0.0 maintenance drift with local impact.** The interval adds notice of CIR (EU) 2026/1730, 2026/1731, and 2026/1735 and revises HLR `ISSU_33b` so Wallet Providers support attestations in the Commission-managed catalogue of attestation schemes. | Updated the legal/reference baseline and implementation checklist; retained ARF 3.0.0 as the synchronization target because no new tagged release was detected. | `REFERENCES.md`, `docs/legal-baseline-2026.md`, and `docs/implementation-checklist.md` now expose the amendment check and catalogue-support implementation obligation. |
| #6 | `sts` | Default branch moved from `b53874f` to `230cd75d`; `docs/technical-specifications/` changed. | **Accepted substantive STS maintenance drift.** The detected interval updates TS5 and TS6 around relying-party registration information, Wallet-Relying Party Service structures, schemas, metadata, and related lifecycle semantics. | Kept STS as the authoritative technical-specification source and added an explicit TS5/TS6 implementation/evidence checkpoint rather than copying volatile schemas into this companion repository. | `docs/architecture-layer-map.md` and `docs/implementation-checklist.md` now require current TS5/TS6 alignment and evidence of the implemented revision/schema set. |
| #7 | `eudi_wallet_portal` | The monitor reported `content_hash_changed` when the configured portal policy had already disabled full-page hashing (`page_hash: false`), causing the legacy stored hash to transition to `null`. Watched semantic fragments did not change. | **Monitoring-state transition; not portal content drift.** | Changed drift classification so a disabled page hash is never compared as content evidence. Added a regression test covering legacy-hash → disabled-hash transition. | `scripts/check_upstream_sync.py` and `tests/test_check_upstream_sync.py` prevent recurrence; the state snapshot is already re-baselined with `content_hash: null`. |

## Authority and assurance conclusion

The ARF and STS findings are real upstream maintenance changes, but neither represents a new tagged ARF release or a reason to duplicate upstream specifications locally. The companion pack therefore absorbs only the implementation-facing consequences: amendment awareness, catalogue-backed attestation support, and explicit TS5/TS6 revision evidence.

The portal finding is different: it was generated by a monitoring-policy transition rather than by semantic upstream movement. The fix makes that distinction machine-verifiable so the issue can close without weakening future fragment monitoring.

## Closure criteria satisfied

- local documentation synchronized to the reviewed ARF and STS changes
- no-change rationale and monitor correction recorded for the portal issue
- regression test added for the false-positive class
- machine-readable upstream state already reflects the accepted snapshots
- commit metadata closes issues #5, #6, and #7 atomically
